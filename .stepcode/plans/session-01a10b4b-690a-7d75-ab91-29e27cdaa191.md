## 0. 先说结论（TL;DR）

| 要加的列 | 怎么算 | 可信度 |
|---|---|---|
| **评分** 0~100 | 阶段一查表（命中规则的历史胜率加权），阶段二换逻辑回归 | 阶段一样本内；阶段二需 holdout 验证 |
| **买入价** | = 当前收盘价（不是预测，是入场点） | 已知 |
| **目标价** | 收盘价 × (1 + 命中规则的历史平均收益) | 样本内 |
| **止损价** | 收盘价 × (1 + 历史收益 10 分位) | 样本内 |
| **盈亏比** | (目标−买入)/(买入−止损) | 样本内组合 |

**核心判断：这两列都能做，且大部分不用新模型——回测报告里已经有 80% 的原料。**
但有一个必须正视的前提：`RSI超卖·放量` 的超额三年从 +41.2pp 衰减到 +8.7pp
（见 `docs/project-structure.md` 顶部）。所以这些数字**只能当排序参考，
不能当收益承诺**，界面上必须标注样本区间和数据截止日。

## 2. 评分方案（三选一，推荐 A→B）

### 方案 A：规则历史胜率聚合（零训练，当天可交付）

对某只股票，设它命中的规则集合 R（含当前勾选的组合规则）：

```
rawScore(R) = Σ_{r∈R} w_r · winRate_r(10日, 全样本)
             w_r = count_r / Σ count_r        ← 按信号量加权，防止 2 个信号的规则
                                                把 7000 个信号的规则带偏
```

再转成 0~100 的相对分（**这才是可排序、可比的东西**）：

```
score = clamp( (rawScore − 当年基准胜率) / (最好规则超额) × 50 + 50 , 0, 100 )
```

例：命中 `RSI超卖·放量` 单规则 → raw=85.2%，基准 49.8%
→ score ≈ (85.2−49.8)/(86.4−49.8)×50+50 ≈ **95**

优点：当天可交付、零训练、完全可解释（用户问"凭啥 95 分"能答）。
缺点：只用了"命中与否"这个 0/1 信息，没区分 RSI=15 和 RSI=19、
量比=1.6 和量比=4.0——而这两个很可能不一样。

### 方案 B：逻辑回归（推荐，阶段二）

```
P(10日涨幅 > 0) = sigmoid( w·x + b )
x = [rsi14, volumeRatio, amountRatio, closePos, bias60, bias250,
     ma60Trend5, k, d, dif, dea, bullAlignment,
     one-hot(命中的规则...), one-hot(所属行业)] 
```

- 标签：3 年里每个 (股票, 交易日) 的 10 日前向收益符号
- 训练：**2024+2025，2026 全程 holdout**，报 AUC / 校准曲线
- 推理：一个点积 + sigmoid，Dart 侧 30 行搞定，系数存 JSON
- 训练用 Python + sklearn（不在 Dart 里做，Dart 没有生态）

优点：真正用上连续特征；有 AUC 这个可验证数字；如果 2026 上 AUC≈0.5
就证伪了，比方案A更诚实。
缺点：需要一次性搭训练管线（约半天到一天）。

### 方案 C：GBDT（**本次不做**）

效果最好但推理要 ONNX 或手写树遍历，模型文件几百 KB，
而这个项目的数据量（3 年、20 条规则）撑不起它的优势。记在这里备查。

> **A 与 B 必须共用同一个接口**：`double scoreOf(IndicatorSnapshot, List<String> hitRuleIds)`。
> 这样 A 先上线、B 训练好后原地替换，UI 和 CSV 一行都不用改。

### 评分怎么变出来——排序键

评分只用于排序，不直接显示概率（避免误导）。显示建议：

- 表格列：`评分` 显示 **0~100 整数**，或 `A/B/C` 档（≥85 高 / 70~85 中 / <70 低）
- 悬停/详情页显示真实概率 + 样本区间 + 命中了哪些规则
- **默认按评分降序排**，用户点表头可切换

## 3. 买卖预测价方案

### 3.1 原则：不做点预测，做分布预测

单点目标价必然错。用策略自身的历史收益分位数给区间，这是诚实的：

| 列 | 公式 | 数据来源 |
|---|---|---|
| 买入价 | = 当前收盘价 | 已知 |
| 目标价(乐观) | close × (1 + p75_10日) | 需补 p75 |
| 目标价(中性) | close × (1 + avgReturn_10日) | 已有 |
| 止损价 | close × (1 + p10_10日) | 需补 p10 |
| 盈亏比 | (中性目标−买入)/(买入−止损) | 派生 |

以 `RSI超卖·放量` 为例（10 日，全样本）：avg +18.35%，
若 p10 ≈ −5% → 目标 = close×1.1835，止损 = close×0.95，
盈亏比 ≈ 18.35/5 ≈ **3.7**。这和报告里 PF 12.42 是同一件事的两种说法，
互相印证得起来（PF 高但盈亏比中等，说明**赢的次数多但赢得不多**，
这正是要盯着衰减曲线的原因）。

### 3.2 多规则命中怎么合并

和评分同源：按 count 加权聚合 avgReturn / p10 / p75。
单规则时退化成该规则自己的数字——**这种情况必须在 UI 上说明
"仅 1 条规则命中，置信度低"**。

### 3.3 需要补的数据

`BacktestStats`（`lib/core/backtest.dart`）加 5 个字段：

```
p10, p25, p75, p90, stdDev
```

`tool/report_all.dart` 里累积分位数。**注意**：分位数计算要在
20 条规则 × 3 持有期 × 3 年上做，内存要留意（当前是全市场扫一遍）。
加完之后**旧报告文件不兼容**，要么版本号升一下，要么 `ReportStore`
对无分位字段的旧报告降级（隐藏止损列），不能崩。

## 5. 验证方案（本节比实现更重要）

所有数字都是样本内的，所以必须至少回答三个问题：

1. **评分有没有区分度？** → 算 AUC。若 2026 holdout 上 AUC ≈ 0.5，
   说明评分等于随机，**这时应该删掉这个功能而不是上线**。
2. **评分校准吗？** → 校准曲线。说 80 分是不是真有 ~80% 胜率。
   不校准的分数排序有效但数值误导。
3. **买卖价有没有用？** → 止损触发率 + 目标达成率。若止损触发 >50%，
   说明 p10 定得太紧，要放宽或干脆不显示止损。

**最低验收线**（达不到就不上线）：
- 2026 年 holdout AUC ≥ 0.58（比 0.5 好，但不夸张）
- 校准误差 ≤ 5pp
- 每条规则的样本量足够（单规则 ≥30 个信号，否则标"样本不足"不给分）
