# 60 日线「有效突破」固定规则

## 目标

新增**两条**复合规则，覆盖有效突破的两种模式（已确认）：

| 规则 id | 模式 | 触发日 | 特征 |
|---|---|---|---|
| `ma60_breakout_confirmed` | A 强势直接站稳 | 突破后第 3 日 | 突破即沿 MA60 上方走，不给回踩机会。命中数较多 |
| `ma60_breakout_pullback` | B 突破→回踩→再启动 | 回踩后再放量阳线当日 | 缩量回踩不破 MA60，再放量越过回踩高点。命中数少、置信度高 |

**为什么拆两条而不是合成一条更严的**：把"回踩不破 + 再放量"设为硬性条件，
会把所有不给回踩机会的强势股全部漏掉，过拟合并让命中数趋近于 0。
两条规则可单选、可对比命中数、也可 AND 叠加。

**资金流入分两步**：本次只用 OHLCV 代理（收盘位置 + 成交额比 + 量比区间），
真·主力净流入放 Phase 2（用户已确认"代理先行，两个都要"）。

## 关于"再加 E/F/G 是否更准、胜率更高"

先说三个必须接受的前提，否则下面的分析没有意义：

1. **本项目目前没有任何回测框架**——没有"信号日 → 未来 5/10/20 日收益分布/胜率/盈亏比"
   的评估器。所以在能跑出这个之前，**无法证明任何一条过滤提高了胜率**，只能证明它
   减少了命中数（这个是能立刻看到的）。这本身是最该先做的一步，见 Phase 2。
2. **胜率 ↑ ≠ 收益 ↑**。每加一层过滤，频率和盈亏比同时下降。市场上大量"高胜率"
   策略是拿极低的频率换的。加过滤前要明确自己想要"更少但更准"还是"更多但平均"。
3. **边际信息递减**。A/B 两条规则已含 突破/站稳/量能/位置/趋势 五类独立信息。
   第 6、第 7 类过滤通常只是在同一批本已很强的股票里再筛，
   命中数掉得往往比胜率升得快——这是过拟合的典型形态。

### E. 形态结构（箱体/双底/圆弧底）—— **明确不做**

**为什么不做：**
- **没有唯一解**。同一张图上十个人画出十个箱体边界。要做成可复现的规则，
  必须把每类形态写成严格数学判据（"近 N 日振幅 ≤ X% 且下沿被测试 ≥2 次且…"），
  这等于发明一套自己的形态语言，且**判定阈值没有客观依据**——纯粹是样本内调参。
- 机械形态识别在 A 股误判率天然偏高：除权跳空、涨跌停封板、停牌复牌都会打断形态连续性。
- 研究结论本身不一致：形态学的实证预测力远弱于趋势/动量类指标。

**E 里唯一值得做的廉价部分：均线多头排列** `MA5 > MA10 > MA20 > MA60`。
这是纯算术、有唯一解、零新增数据，业内对"只做趋势内突破"有一致结论。
→ **纳入一期，作为可关过滤项**（默认开）。

### F. 大周期（半年线/年线/周线）—— **收益最确定，但依赖扩数据**

**为什么一期没做：**
- 本地库回填 **120 个交易日**。MA250（年线）需要 250 根，MA120（半年线）需要 120 根
  —— 一个都算不出来。周线 MA60 要 300 根，更远。
- 且 `SyncService` 是水位线增量（只拉 `MAX(trade_date)` 之后的日期），
  补历史 130 天需要**新增"补拉指定日期区间"的同步模式**，不是改个默认值就行。

**做了是否更准：大概率是，而且是三项里最确定的。** 业内高度一致：
"下降趋势中的突破 99% 是诱多""周线向下时日线突破信号要打折"。
用 MA250 位置过滤，本质是加一层"中期趋势方向"的确认，信息与日线 MA60 不共线。

**但有两个坑：**
- 同样是"碰到年线"，**年线在头顶 5%** 和 **头顶 50%** 是两回事。
  正确做法不是"必须站在年线上方"，而是拆成两个可关项：
  - `ma250_filter`：MA250 走平或上翘（别在年线明确下行时接飞刀）
  - `above_ma250` / 或"距 MA250 乖离 ≤15%"（避开刚撞年线压力的位置）
- 成本边界：已入库 120 天，补到 250 只需再拉 130 天 × 每天 1 次全市场请求
  （限频 50 次/分），实际约 10~20 分钟，可断点续传。**不痛苦，但需要新增同步模式。**

→ **列为 Phase 1.5**：紧跟一期，先扩数据再加规则，不塞进本次交付。

### G. 真·资金流入 —— **边际价值被高估，维持"代理先行"**

**为什么一期没做：** 数据源问题（tushare 要积分，东财免 token 但逐股请求）。

**更要紧的是三个方法论问题：**
- **口径陷阱**：东财"主力"是按**单笔成交金额分档**（超大单/大单/中单/小单）统计的，
  是**委托规模，不是真实身份**。量化拆单、ETF 做市、大宗对手方都会污染它。
  "大单 = 机构"是常见误读，拿它做过滤会得到"看起来更准"但实际不可靠的信号。
- **与 OHLCV 代理高度共线**：日频资金流的预测力很弱，而"放量 + 收盘位于振幅上半部"
  本身已近似等价于"当日主动性买盘占优"。**Phase 1 的代理已经拿到了当日口径的大部分
  信息增量**。真·资金流的增量主要在**连续性**（连续 3~5 日净流入），那是日 K 拿不到的。
- **同步完成度会让选股结果有偏**：逐股同步 5000 只期间，已同步的股票有资格参选、
  未同步的没有 → 规则输出不可比。必须设计成"无资金流数据一律不参选"且 UI 明示。

→ **Phase 2 若做，重点放在「连续 N 日主力净流入占比 > 0」，而不是「当日净流入 > 0」。**

## 判据

### A. `ma60_breakout_confirmed` — 突破并站稳（窗口 11 日）

| 维度 | 条件 | 默认阈值 |
|---|---|---|
| 突破 | 最近 N 日内发生过 MA60 上穿 | N=5 |
| 站稳 | 突破日距末日 ≥3 日，且其间每日收盘 > 当日 MA60 | 3 日 |
| 幅度 | 乖离率下限 | ≥3% |
| 不追高 | 乖离率上限 | ≤15% |
| 不深破 | 站稳期每日最低价 ≥ 当日 MA60 × (1−tol) | tol=2% |
| 位置 | 突破前 5 日中至少 4 日收盘在线下（区分首次突破 vs 高位反复穿越） | 5 / 4 |
| 量能 | 突破日量比区间 | 1.5 ~ 6.0 |
| 成交额 | 突破日成交额 / 前 5 日均额 | ≥1.5 |
| 趋势 | MA60 近 5 日变化 ≥0（走平或上翘） | ≥0 |
| 资金代理 | 突破日收盘价位于当日振幅上半部 | (close−low)/(high−low) ≥0.5 |
| 多头排列 | MA5 > MA10 > MA20 > MA60（E 的廉价部分，可关） | 严序 |

### B. `ma60_breakout_pullback` — 突破后回踩确认（窗口 20 日）

触发日是「再放量阳线」当日，不是突破当日；突破日须在信号日前 8~14 个交易日。

| 维度 | 条件 | 默认阈值 |
|---|---|---|
| 突破 | 窗口内发生过 MA60 上穿，且突破日距末日 ≥8 日 | gap≥8 |
| 突破质量 | 突破日乖离 ≥3%、量比 ≥1.5、突破前 5 日至少 4 日在线下 | 同 A |
| 回踩发生 | 突破日之后至少 1 日 `low ≤ MA60×(1+touch)`（真踩到线附近） | touch=3% |
| 回踩不破 | 回踩段每日 `close > MA60` 且 `low ≥ MA60×(1−tol)` | tol=2% |
| 缩量回踩 | 回踩段最大日成交量 ≤ 突破日成交量 × s | s=0.8 |
| 再启动 | 末日 `close > open`（阳线）、量比 ≥1.5、收盘在振幅上半部 | 同 A |
| 越过回踩高点 | 末日收盘 > 回踩段最高收盘价 | — |
| 不追高 | 乖离率 ≤15%、MA60 近 5 日变化 ≥0 | 同 A |
| 多头排列 | MA5 > MA10 > MA20 > MA60（可关） | 严序 |

## 关键设计决定

**1. `IndicatorSnapshot.minBars` 保持 20，新字段设可空。**
模式 A 需 70 根、模式 B 需 79 根。若把 minBars 提上去，20~78 根历史的股票会被
**所有**规则静默剔除；且 `test/fixtures.dart` 的 40 根序列 + python oracle 基准
（`closesVRecovery()` 顶部注释）全部要重写。改为 `ma60: double?`、
`window: BreakoutWindow?`、`pullbackWindow: BreakoutWindow?`，规则内 null 返回 false：
现有 7 条规则与它们的测试零改动，20 根以上的股票仍参与其它规则。

**2. 近端窗口抽成 `BreakoutWindow`，不往快照里塞 40 个平铺字段。**
突破/站稳/回踩/再启动四件事都要看"多天前后关系"，平铺字段不现实。
窗口带长度参数（A=11、B=20），存 `opens/closes/lows/volumes/volumeRatios/ma60`
六条等长列表 + `crossUpIndex` getter。

**3. 量能一律取「突破日」而不是末日。** 站稳后末日缩量是正常洗盘，
若用末日量比会把好形态误杀。

**4. 两条规则不共享同一窗口。** A 的语义是"突破新鲜（5 日内）+ 站稳"，
B 的语义是"突破较久（8~14 日前）+ 已回踩确认"。共用一个 20 日窗口会让 A 的
突破信号陈旧（20 日前突破仍算"新突破"），失去筛选意义。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 模式 B 阈值过严导致 0 命中 | 阈值全部抽成可调常量；上线先用 `dart run bin/screen.dart ma60_breakout_pullback` 实测命中数再收紧/放宽 |
| 模式 B 过拟合 | 已与模式 A 拆成两条，用户可自行对比两者命中集，不必二选对 |
| 多头排列过滤过严 | `bullAlignmentRequired` 做成开关常量 + 单测覆盖关态 |
| `amount` 为 0 导致成交额比失效 | 任一日 ≤0 即返回 0，规则自然不满足（不抛异常） |
| 两个窗口 per stock 带来重复计算 | 仅 11+20 日切片，5000 股量级可忽略 |
| 新增可空字段影响 isolate 传输 | 纯数据类，`BreakoutWindow` 为普通 final 字段类，无问题 |

## Phase 1.5（紧接一期，扩数据 + 大周期过滤）

1. `bin/sync.dart` 新增「补拉指定日期区间」模式（`SyncService.sync` 加 `fromDate` 参数），
   因为水位线增量补不了 `MAX(trade_date)` 之前的历史
2. `backfillDays` 默认 120 → 250（新用户首次即够算 MA250/MA120）
3. 已入库 120 天的老用户跑一次补拉 130 天（约 10~20 分钟，可断点）
4. 新增规则：
   - `ma250_up` MA250走平或上翘（别在年线明确下行时接飞刀）
   - `near_ma250` 距 MA250 乖离 ≤15%（避开刚撞年线压力的位置）
5. 这两条**默认不选**，作为 A/B 的可选加强组合，由用户回测后自行决定

## Phase 2（按优先级）

1. **回测框架（最高优先，没有它无法证明任何规则"更准"）**
   - `bin/backtest.dart` + `lib/core/backtest.dart`：对信号日统计未来 5/10/20 日的
     收益分布、胜率、盈亏比、最大回撤；支持对同一起点集合做"加/不加某过滤"的对比
   - 120 日数据样本期偏短且只覆盖一段行情，只能看出**明显**差异，不能定论——
     这一点要在输出里写明，避免误读
2. **真·资金流**（东财 `fflow/daykline`）：
   - `fund_flow` 表 + 逐股同步（限速、降级、**不阻塞日线同步**）
   - **无资金流数据的股票一律不参选**，UI 明示数据完成度，避免选股集合有偏
   - 新增规则 `main_capital_inflow_n`「连续 N 日主力净流入占比 > 0」——
     刻意不做"当日净流入 > 0"，因为与 Phase 1 的 OHLCV 代理高度共线
   - 给两条有效突破规则追加该项，把代理换成真·资金流
